# Documentation style guide

Write practical explanations that help readers understand the data flow, choose
a workflow, and complete the next step.

- **Start with purpose and flow.** Explain what enters the system, how it
  changes, and what comes out. Use a small diagram when it makes the sequence
  easier to understand.
- **Organize around tasks.** Describe the reader's starting point, actions,
  decisions, and results. Assume a capable reader; avoid prescribing staffing,
  job titles, or authority to perform the work.
- **Use plain, direct language.** Prefer short, familiar headings, concrete
  verbs, and active instructions. Keep necessary technical terms and use them
  consistently. Remove introductions that merely announce the page's contents.
- **Describe what happens and what to do.** Remove repeated disclaimers,
  negative qualifications, and policy reminders. Keep restrictions where they
  affect a concrete decision or prevent a mistake, and explain the consequence.
- **Keep information with its audience.** Put task instructions in user guides,
  implementation rules in technical references, and repository or AI conventions
  in their dedicated files. Link to the relevant explanation instead of
  repeating it.
- **Make examples usable in place.** Name the file being edited, show commands
  in order, and mark manual review steps. Add short comments that explain the
  purpose of each command or group. Identify placeholders clearly.
- **Explain timing and reuse.** Distinguish setup per specification version,
  configuration per site, and recurring runtime work. State what each stage
  produces and hands over, including what can be shared between sites.
- **Preserve accuracy while simplifying.** Keep command behavior, artifact
  identities, and ownership boundaries correct. Describe optional features and
  future plans accurately. Keep volatile counts and temporary state in generated
  evidence rather than durable prose.

Use numbered steps for sequences, tables for comparisons, and paragraphs for
connected explanations. Add detail when it helps the reader act correctly.
